## Task

Plan and build a component library for gpuix-fractalsvelte: actions, inputs, layouts, overlays, navigation and feedback. It needs customisable themes and props, plus documentation for each component. The user chose a new package at `fractaldesign/packages/gpuix-fractalsvelte-ui`. The arhat app was out of scope.

## Decisions

- **Theming:** `var(--ui-<token>)` set by `ThemeProvider` through `set_css_vars`. This gives one-frame runtime theme switches with no recompile. The token contract lives in `src/theme/tokens.ts`. Four themes ship: light, dark, mandala, midnight. `create_theme` derives new ones.
- **Shared props:** every component uses the same vocabulary: `size` sm|md|lg, `tone`, `variant`, `style`, `testid`, controlled `value` + `onchange`, and `open` + `onclose`. Nothing uses `bind:`.
- **GPUI workarounds:**
  - Focus is drawn as a border-colour ring, tracked through `onfocus`/`onblur`, because GPUI has no `:focus`.
  - Disabled states gate their hover rules behind an `.on` class, because a `:hover` rule outranks a plain class.
  - Overlays reuse the base package's `Portal`, `Popover`, `Tooltip` and `Scroller`.
- **Build process:** I wrote the foundation and two reference components (Button, Modal). `CONVENTIONS.md` is the brief for builders. Seven Haiku agents (pi, `anthropic/claude-haiku-5-5`) built the other categories in parallel. Each agent could only create its own files. Shared files (`src/index.ts`, `gallery/registry.ts`) are generated by `scripts/gen.ts`, so the agents never conflicted. Three more Haiku agents filled in docs and demos that API aborts had cut off, and one fixed test typings.

## Follow-up fixes

- **ButtonGroup join:** `src/group.svelte.ts` adds a context. `ButtonGroup` provides it. `Button`, `IconButton` and `Toggle` register in mount order and get a first/middle/last/only position. They square their inner corners and overlap borders by 1px. The test asserts the 1px overlap.
- **The "Tooltip offset" was a bounds bug:** the tip painted correctly. Native `getElementBounds` (prebuilt `@gpuix/native` 0.10.0) returns the content origin (border plus padding inside the box) together with the padding-box size. Every bounds read was shifted by the element's padding, and borders were dropped from the size.
  - Fixed in gpuix-fractalsvelte `src/renderer.ts`: `apply_style` records each element's padding and border insets. `get_native()` returns a proxy that corrects `getElementBounds` and `getAutomationTree` to the painted border box.
  - Verified against the pixels of a screenshot (padded, bordered, rem-padded and single-value-shorthand boxes). The Tooltip now measures exactly gap-correct on all four sides.
  - Base suites: the same 5 suites fail before and after the change (fractalstyler, host, overlay, window, tooltip's 0.5px rounding check), so these are pre-existing failures.
  - The upstream native bug still needs reporting to remorses/gpuix.
- **Svelte split:** the UI package now installs the same vendored svelte tgz as gpuix-fractalsvelte (plus an override). The `as Snippet` casts are gone.

## jsrepo registry

- `jsrepo.config.ts` lists one item per component, built from `src/components` and the doc frontmatter (title, description, category). Each item includes its doc page (role `doc`) and gallery demo (role `example`). There are 3 shared items:
  - `theme`, added on init
  - `types`, added only when needed
  - `group`, added only when needed
- Every component depends on `theme`. `svelte` and `gpuix-fractalsvelte` are excluded as dependencies, since the consumer's app already provides them.
- `bun run registry` regenerates the index and gallery list, then builds `registry.json` with the `repository` output. The result is 40 items.
- Hosted at github.com/fractalmandala/gpuix-fractalsvelte-ui, master branch (commit 60d60ee).
- Verification: installed into a fresh copy of the starter, first from the local filesystem and then from GitHub (`github/fractalmandala/gpuix-fractalsvelte-ui/button` and `/modal`). The shared pieces came along, and imports were rewritten to the consumer's `paths`. The headless test passed and svelte-check reported 0 errors.

- Removed again. Distribution is npm-first, and the components will change a lot for now, so keeping `registry.json` rebuilt isn't worth it. jsrepo can be re-added later; its config is generated from the component folder.
